## Goal

1. **`buildUrl(lat, lon, horizon)`** — horizon `'24h'` ⇒ `forecast_days=2` (current behaviour, unchanged); horizon `'7d'` ⇒ `forecast_days=7`. Everything else identical: same fields (`hourly` + `minutely_15`), `wind_speed_unit=mph`, `timezone=America%2FChicago`, `past_days=1`. Keep the default parameter so existing callers behave identically.

2. **`expandHourlyVector(hourlyEntries, gammaDeg)`** — build 15-min entries from hourly model samples for days 3–7 using **Cartesian vector interpolation**:
   - decompose, θ = `dirTrueDeg` (meteorological bearing = direction the wind comes FROM):
     `u = −s·sin(θ)`, `v = −s·cos(θ)` (θ in radians)
   - for each adjacent hour pair, at `f ∈ {0, 0.25, 0.5, 0.75}`:
     `u_f = (1−f)·u_0 + f·u_1`, `v_f = (1−f)·v_0 + f·v_1`
   - reconstruct: `speedMph = hypot(u_f, v_f)`,
     `dirTrueDeg = (atan2(−u_f, −v_f)·180/π + 360) mod 360`
   - `gustMph`: **linear** blend of the gust speeds (the API gives no gust direction — this matches the existing `interpolate15` behaviour; put that rationale in a code comment)
   - `bearingGrid = gammaToGrid(dirTrueDeg, gammaDeg)` — reuse the existing helper
   - entry shape MUST equal what `buildSeriesFrom` produces: `{ time, speedMph, gustMph, dirTrueDeg, bearingGrid, tEffH }`, `time` = `'YYYY-MM-DDTHH:MM'` local.
   - **Hour anchors are exact**: at `f = 0` the frame equals the source hourly sample bit-for-bit (speed and bearing).

3. **`selectRange(series, startDateStr, days)`** — entries whose local date lies in `[startDateStr, startDateStr + days)`; `startDateStr` = `'YYYY-MM-DD'` (America/Chicago local).

4. **`ingest(opts)`** — accept `opts.horizon` (`'24h'` default, `'7d'`):
   - `'24h'`: **byte-identical behaviour to today** (native `minutely_15` ⇒ `buildSeriesFrom` ⇒ `selectDay`).
   - `'7d'`: assemble ONE series — native `minutely_15` entries for the first two local days (today + tomorrow), then **hourly-vector-expanded** entries for the remaining days (days 3–7), contiguous, no duplicates, no gaps. **Ignore the API's `minutely_15` values beyond the 48 h boundary** (they are the API's own interpolation of the same hourly data; we own ours). Then run the existing single `computeTeff(series, STEP_H = 0.25)` pass over the whole assembled series (t_eff keeps its cross-midnight history from `past_days=1`), then slice with `selectRange(series, today, 7)`.
   - Return shape keeps the existing field names: `day` = the active window array (96 entries for `'24h'`, **672** for `'7d'`), plus `stepMin: 15`, plus new `horizon`. `currentIndex` keeps working on the returned window.
   - `buildSeriesFrom` stays the single 15-min construction path (wind.test.js `[2b]` guards this) — the blended entries must flow through the same builder, not a parallel one.
   - The existing `interpolate15` (4× hourly expansion, angle-lerp) is the **fallback** path when `minutely_15` is missing — do not delete it.
