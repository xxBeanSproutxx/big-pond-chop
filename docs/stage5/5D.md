## Goal

1. **Day partitions (pure helper, exported, date-string based).** `dayPartitions(entries)` → `[{ date, index }, …]`: one entry per maximal run of `time.slice(0, 10)` (local date), `index` = first frame of the run, in order. MUST derive from the date strings — NOT `floor(i/96)` (5A guarantees 96/day today; the code must not assume it).

2. **Timeline DOM** (`renderTimeline()`, called from `applyWindData` and whenever the viewport width class changes; re-render debounced on `resize`):
   - `#track-days`: one divider per partition — a 1 px vertical line at rail x = `11 + (index/(n−1))·(trackW − 22)` (same mapping as the playhead), ≥ 24 px tall, muted — plus a label anchored at the divider: `ui.dayLabel(entries[index].time, long)`, where `long = window.innerWidth >= 414` → `"Fri 11"` (< 414) / `"Friday 11"` (≥ 414), ~9 px, one line, near the bottom edge of the 52 px row, no clip at the last divider.
   - `#track-ticks`: when `window.innerWidth >= 768` render one thin tick per HOURLY frame (`time.slice(14, 16) === '00'`) across the whole ACTIVE window — 168 ticks in `'7d'`, 24 in `'24h'`. When `< 768`: no ticks; in `'7d'` ALSO render a hatch element spanning days 3–7 (left = rail x of `partition[2].index`, right = rail x at `t = 1`), a subtle repeating-linear-gradient stripe, `aria-hidden`, pointer-events none. (Guardrail reading: hatch is the narrow fallback; full hourly ticks are the ≥ 768 render.)
   - `#track-label`: `'7 day · hourly → 15 min'` in `'7d'`, `'24 h · 15 min'` in `'24h'` (exact strings).
   - `#deck-day`: set in `showFrame` to `ui.dayLabel(e.time, long)` — same responsive rule as the dividers.
   - ALL timeline elements must be `pointer-events: none` (children of the three 5B containers inherit it) — the scrub surface, keyboard and buttons must keep working untouched.

3. **Horizon state machine** (`#h-24h` / `#h-7d`):
   - Boot: resolve horizon = valid `?h=` (`'7d'`/`'24h'`) → else `localStorage['bpc.horizon']` → else `'24h'`; ingest with it; write the resolved value to BOTH `localStorage['bpc.horizon']` AND the URL (`history.replaceState`, `?h=` merged over the existing params). Wrap storage access so it can never throw-crash boot.
   - Widen (`'24h' → '7d'`): re-entry guard while a fetch is in flight; show the loading skeleton via the existing `boot()` helper with the EXACT text `Loading 7-day wind…` and the indeterminate bar; `await wind.ingest({ point, gamma, horizon: '7d' })`; on success remember the result (`full7d`), persist, apply; on failure keep the old horizon, hide boot, show the existing retry note (retry re-attempts the widen).
   - Narrow (`'7d' → '24h'`): slice the in-memory `full7d.day` via `wind.firstDaySlice(...)` and apply — **ZERO network refetch** (no `ingest`/fetch on this path).
   - On toggle (both directions) the playhead SNAPS to `data.currentIndex` (nowIdx) — do NOT preserve the previous `cur`; `aria-pressed` on both buttons reflects the ACTIVE horizon once applied. At BOOT the `?hour=`/`?frame=` overrides keep working exactly as today.
   - `#refresh` / retry (`refreshWind`): ingest the ACTIVE horizon (not the `'24h'` default); a 7-day refresh also updates the `full7d` cache.

4. **7-day playback cadence.** Pure helpers `playStep(horizon)` (`'7d'` → 4, else 1) and `nextPlayIdx(cur, step, n)` = `(cur + step) % n`. The interval advances by the step of the ACTIVE horizon: `'7d'` = +4 frames (1 h) per 333 ms tick (672/4·0.333 ≈ 56 s loop), wrapping cleanly by modulo at the boundary — from frame 671 the next tick lands on 3 (never a stall at 671). `prefetch` uses the same step. 24 h keeps +1.

5. **NOW hairline + shim removal + aria.**
   - `#now-tick`: SAME rail mapping as the playhead (`left = 11 + t·(trackW − 22)` px, `t = nowIdx/(n−1)`, `transform: translateX(-50%)`) in BOTH modes; updated whenever the window changes (boot, both toggles, refresh); still hidden under `?hour=`/`?frame=`.
   - Remove `#scrub`: delete the `<input id="scrub" …>` from `index.html`; delete the shim reads/writes in `render.js` (the `getElementById('scrub')` const, `scrub.value =`, the `input` listener, `scrub.min`/`scrub.max` writes — `aria-valuemax` already carries the max). `tests/render.test.js` [4] asserts the shim GONE and the timeline containers present; `tools/qa/stage4_check.py` [2] + [7b] read `#track` `aria-valuemax`/`aria-valuenow` instead of `#scrub`.
   - `aria-valuetext` = `"<formatClockLocal>, <dayLabel long>"` (the 5C handoff: 5D appends the day label) — e.g. `4:30 PM CDT, Friday 11`.
